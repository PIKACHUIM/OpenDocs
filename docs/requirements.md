# 需求说明

## 1. 背景

团队需要一个**可自托管**的在线文档系统：既要能画（白板/思维导图），也要能写（文档、表格、演示），
且不希望为了几类文档维护多套账号与分享体系。SaaS 产品无法满足数据留在自有账号下的要求，
开源方案又往往只覆盖单一形态。

OpenDocs 的目标是把这几类文档收进一个系统：**一套账号、一套目录、一套分享、一次部署**。

## 2. 目标与非目标

### 目标

- 五类文档（白板/思维导图、Markdown、Word、Excel、演示文稿）在同一工作台内创建与管理
- 账号、权限、分享、管理后台齐备，可直接对外提供使用
- 前端纯静态、后端可跑在边缘运行时，部署成本接近零
- 未注册用户能低成本体验，降低试用门槛

### 非目标

- 不做实时多人协同光标（当前为乐观锁 + 防抖保存）
- 不做完整 Office 排版引擎（分页、页眉页脚、复杂公式）
- 不做企业级组织架构、SSO、审计日志
- 不做移动端原生应用

## 3. 角色

| 角色 | 能力 |
| --- | --- |
| 访客（未登录） | 浏览首页、免登录试用编辑器、通过分享链接查看/编辑（取决于分享模式） |
| 用户 | 创建与管理自己的文档、目录；参与被分享的文档 |
| 协作者 | 对指定文档具备只读或可编辑权限（由所有者授予） |
| 管理员 | 用户管理、文档管理、邀请码管理、系统设置 |

## 4. 功能需求

优先级：P0 = 必须，P1 = 重要，P2 = 可选。

### 4.1 账号

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| A1 | 邮箱 + 密码注册，密码不少于 8 位 | P0 |
| A2 | 登录/登出，会话保持 7 天，HttpOnly Cookie | P0 |
| A3 | 首个注册用户自动成为管理员（可关闭） | P0 |
| A4 | 邮箱验证、找回密码（依赖邮件服务配置） | P1 |
| A5 | 修改密码；管理员可重置任意用户密码 | P1 |
| A6 | 注册总开关（关闭后仅管理员可建号） | P0 |
| A7 | **邀请码注册**：开启后必须提供有效邀请码 | P0 |
| A8 | 邀请码管理：自定义码或自动生成、可用次数、有效期、备注、启停、删除 | P0 |
| A9 | 邀请码名额扣减需并发安全（不超卖） | P0 |

### 4.2 文档

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| D1 | 创建五类文档：白板/思维导图、Markdown、Word、Excel、演示文稿 | P0 |
| D2 | 打开、编辑、自动保存（防抖 1.5s） | P0 |
| D3 | 重命名、创建副本、移入回收站、恢复、永久删除 | P0 |
| D4 | 乐观锁：版本冲突时提示而非覆盖 | P0 |
| D5 | 导出：`.drawnix` / Markdown / PDF / `.docx` / `.xlsx` / `.pptx` | P1 |
| D6 | 文档正文与图片存对象存储，元数据存 D1 | P0 |
| D7 | 单文档正文上限 8MB，超限给出可读提示 | P1 |

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| O1 | 多级目录：新建、重命名、移动、删除 | P0 |
| O2 | 删除目录时文档上提到父目录，不丢数据 | P0 |
| O3 | 文档移动到任意目录 | P0 |
| O4 | 收藏 / 取消收藏，独立"收藏"视图 | P1 |
| O5 | "最近"视图按最近打开时间排序 | P1 |
| O6 | 列表视图与卡片视图切换，记忆用户偏好 | P1 |
| O7 | 按标题搜索，分页 | P0 |
| O8 | 回收站独立视图 | P0 |

### 4.4 分享与协作

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S1 | 链接分享：只读 / 可编辑两种模式 | P0 |
| S2 | 未登录用户可通过分享链接访问，`edit` 模式可直接保存 | P0 |
| S3 | 撤销分享链接 | P0 |
| S4 | 按注册邮箱邀请协作者，指定只读/可编辑 | P1 |
| S5 | 权限模型：所有者可改一切；协作者按角色；其他人不可见 | P0 |

### 4.5 免登录体验

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| G1 | 首页可直接进入任一编辑器的试用模式 | P0 |
| G2 | 试用内容只存浏览器本地，不产生账号与网络写入 | P0 |
| G3 | 试用后可"登录并保存"，一键转为云端文档 | P0 |
| G4 | 本地白板（`/local`）可离线使用，可另存到账号 | P0 |

### 4.6 管理后台

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M1 | 概览：用户数、文档数、存储占用、类型分布 | P1 |
| M2 | 用户管理：列表、搜索、改角色、禁用、重置密码、删除 | P0 |
| M3 | 文档管理：跨用户列表、搜索、删除 | P1 |
| M4 | 邀请码管理（见 A8） | P0 |
| M5 | 系统设置：站点名称/URL、注册开关、邀请制开关、邮件、人机验证 | P0 |

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 部署 | 前端纯静态；后端可跑在 Cloudflare Workers 与 EdgeOne，无需常驻服务器 |
| 数据主权 | 数据存自有账号下的 D1 + R2/Blob，不经过第三方 |
| 安全 | 密码 PBKDF2-SHA256；会话 token 只存哈希；Cookie HttpOnly + Secure + SameSite=Lax |
| 性能 | 首屏只加载当前编辑器所需代码（按类型懒加载）；静态资源不进入函数 |
| 兼容 | 现代浏览器（Chrome/Edge/Safari 最近两个大版本） |
| 可维护 | 业务代码与平台解耦，新增平台只需写一个薄适配层 |

## 6. 验收标准（MVP）

1. 全新环境按 README 步骤可在 30 分钟内跑通本地开发与一次生产部署。
2. 从注册（含邀请码模式）到创建文档、编辑、自动保存、刷新后内容一致。
3. 目录层级创建/移动/删除后，文档不丢失、归属正确。
4. 未登录用户拿到 `edit` 分享链接可直接编辑并保存成功；拿到 `view` 链接无法写入。
5. 管理员可创建邀请码并限制次数与有效期；用完后注册被拒绝。
6. 本地白板断网可用，联网登录后可一键保存为云端文档。

## 7. 后续版本（未纳入本次范围）

- 实时协同（CRDT / WebSocket，需要 Durable Objects）
- 完整 Office 编辑（建议引入 OnlyOffice 一类服务端引擎）
- 图片/海报设计器
- 文档评论、@提醒、版本历史
- 暗色模式、多选批量操作
